## 四、真件长尾的定性诊断（关键）

往返账里 8/8 份全掉的头三族，逐族按「读手 / 模型 / 包槽 / 写手」取证后，
**没有一族值得本轮改产品码**：

| 族 | 判定 | 依据 |
|---|---|---|
| `cols\|num/space` | **假红，不碰** | 真件源值 `num=1`（单栏，OOXML 缺省态）；写手刻意单栏不写 `w:cols`，语义等价 |
| `docGrid\|charSpace` | **需单独立项** | 源值 `0`；`linePitch`/`type` 同族 kept，网格整体正常。根因是 docx 库真值闸吞了数字 0（`index.mjs:22374`）；先确认 0 是否 Word 缺省，再决定是否单独立项 |
| `bookmarkStart/End\|id/name` | **按纪律不碰** | `w:id` 是引用图（bookmarkEnd 栈式配对、目录域引用）；掉的是 `_goback`/`_toc*` 空/跨段书签，已是已知诚实边界 |
| `kern\|val` | **需单独立项** | 真丢（`kern=2` 也没写回），但与 `characterSpacing`（`w:spacing`）不是同义；牵动 charExtra 一族发送路径，不塞进本轮 |

这说明：**真件百分比低 ≠ 读手退化**。三本账各自量的是不同口径，落差主要来自
「合成夹具只放读手关心的属性」与「真件带大量缺省/主题/视觉属性」，以及若干
已定性的假红。修任何一族都要动写手产品码，会让五本账的 `assertAtRef` 基线全部
失效，属单独立项，不宜在本轮「回归」里顺手做。

## 边界与结论

1. 三本账的百分比**只对应各自这批输入**：夹具 88.5% / 99.0% / 100% 与真件
   68.5% / 85.8% / 32.0% 都是诚实读数，谁也不比谁更「真」——前者描述产品自洽，
   后者描述真实文件。
2. 真件仅 9 份、单一来源（本机教学/办公文件），**不构成统计样本**；pptx/ods
   无真件，不能外推。
3. 本轮只做回归与诊断，**不修产品、不刷分、不动任何主账本**。长尾里可低风险
   修的已在历轮清完，剩下的要么假红、要么需单独立项、要么需真机对撞。
4. xlsx `styles.xml` 的视觉语义保真是目前最大的真缺口（60 对留 5 对），
   建议作为下一轮独立功能立项，而非继续铺量具。
