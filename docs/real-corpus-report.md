## 四、真件长尾的定性诊断（关键）

往返账里 8/8 份全掉的头三族，逐族按「读手 / 模型 / 包槽 / 写手」取证后，
**没有一族值得本轮改产品码**：

| 族 | 判定 | 依据 |
|---|---|---|
| `cols\|num/space` | **假红，不碰** | 真件源值 `num=1`（单栏，OOXML 缺省态）；写手刻意单栏不写 `w:cols`，语义等价 |
| `docGrid\|charSpace` | **需单独立项** | 源值 `0`；`linePitch`/`type` 同族 kept，网格整体正常。根因是 docx 库真值闸吞了数字 0（`index.mjs:22374`）；先确认 0 是否 Word 缺省，再决定是否单独立项 |
| `bookmarkStart/End\|id/name` | **按纪律不碰** | `w:id` 是引用图（bookmarkEnd 栈式配对、目录域引用）；掉的是 `_goback`/`_toc*` 空/跨段书签，已是已知诚实边界 |
| `kern\|val` | **需单独立项** | 真丢（`kern=2` 也没写回），但与 `characterSpacing`（`w:spacing`）不是同义；牵动 charExtra 一族发送路径，不塞进本轮 |

这说明：**真件百分比低 ≠ 读手退化**。三本账各自量的是不同口径，落差主要来自
「合成夹具只放读手关心的属性」与「真件带大量缺省/主题/视觉属性」，以及若干
已定性的假红。修任何一族都要动写手产品码，会让五本账的 `assertAtRef` 基线全部
失效，属单独立项，不宜在本轮「回归」里顺手做。

### 族级口径看不见的东西

族级分子是「元素|属性的**去重值集合**」：`right|style` 源与写出都含 `thin` 就判 kept。
可 R09 里 12 个格子的右边框被写成了左边框——族级账本全绿。

于是补了一把**单元格级对撞**（只读量具，不入账）：解析 src/out 的 `styles.xml`，把每格的
`s=` 解析成语义签名（字号/粗斜下划线/字体色/字体名 + 填充 + 四边"样式+色" + 数字格式 +
对齐），按 `<c r="A1">` 逐格比。解析器必须按标签扫描而不是正则跨元素匹配——写出包把
`<xf .../>` 全挤在一行，`<xf\b.*?</xf>` 会跨过自闭合边界吞掉下一条，整张样式表错位一格。

### 查出来的真 bug：合并区非锚点格的样式被锚点刷掉

R09 源件 `B2:H2` 是合并区，锚点 B2 四边 thin，C2..G2 各自只有上下边、H2 只有右+上+下。
写出包里头全成了 B2 那一份 → 10 格多出一条左边线、2 格右边变左边。六份里 3 份命中，共 23 格
（R09 12、R13 3、R14 8；R10/R11/R12 的非锚点空格样式与锚点相同，看不出差）。

根因两行：`merge_range()` 用锚点格式铺满整片（crate 内部就是逐格 `write_blank(锚点 fmt)`），
紧接着主循环 `if in_merge(..) { continue }` 把区内所有格跳过——各带样式的非锚点空格
就只剩锚点那一份。修法：锚点仍由 `merge_range` 写，非锚点里「有样式且没有值」的格补
`write_blank(自己的 fmt)`；有值的非锚点格维持原样（Excel 不产生这种件，改了要猜语义）。

### 修后读数

| | 修前 | 修后 |
|---|---:|---:|
| 6 份单元格级边框差 | 23 格 | **0** |
| 填充 / 对齐 / 数字格式 / 字体语义差 | 0 | **0** |
| 族级账本（6 份合计） | 204/614（33.2%） | 204/614（33.2%，不动） |

族级数字**不动是对的**：那 23 格是「拿了另一格的样式」，不是「属性缺席」，去重值集合里
两边都含 `thin`。这一笔只能靠单元格级证据，进不了账本——记口径，不记分数。

单元格级剩下的差只有字体 `charset`/`scheme`（crate 有 `set_font_charset`/`set_font_scheme`
但未接线，已知架构限制）；6 份共 1,516 个单元格，其余语义全对。

## 边界与结论

1. 三本账的百分比**只对应各自这批输入**：夹具 88.5% / 99.0% / 100% 与真件
   68.5% / 85.8% / 32.0% 都是诚实读数，谁也不比谁更「真」——前者描述产品自洽，
   后者描述真实文件。
2. 真件仅 14 份（8 docx + 6 xlsx）、**单一来源**（本机教学/办公文件），**不构成统计
   样本**；pptx/ods 无真件，不能外推。xlsx 那 6 份还是同一套模板，扩样只证明了
   「缺口不随输入变」，没证明别的。
3. 前四节的口径与结论是 v0.210 那一轮「只回归、不修产品」的读数；v0.220 的扩样改了一处
   产品码（合并区非锚点样式），读数记在第五节，两节不可混读。
4. xlsx `styles.xml` 的视觉语义保真是目前最大的真缺口（60 对留 5 对），
   建议作为下一轮独立功能立项，而非继续铺量具。
