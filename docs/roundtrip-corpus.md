各份夹具的属性宇宙本就不同，所以「出现份数」普遍偏低是常态——这张表找的是
**跨夹具反复掉的同一枚**（如 `tblLook` 四兄弟），不是按份数排优先级。

其中 **4 枚是已逐对诊断过的口径假红**（`tblLook|firstColumn`, `tblLook|firstRow`, `tblLook|lastColumn`, `tblLook|lastRow`）：
`w:tblLook` 的 `w:val` 位掩码与逐位 ST_OnOff 属性是同一组开关的两种写法，
写出包只发 `w:val` 不丢语义；为凑数字补写显式属性反而会写出与掩码打架的坏件。
**跨夹具复现 ≠ 真丢**，剩下那些才值得逐对看「读手 / 模型 / 包槽 / 写手」四处。

## 跳过明细

- `01-body.docx`：源件含非法 2 位 hex 属性值，写手按 OOXML 规范拒绝（语料缺陷，非产品 bug）：Invalid hex value '0'. Expected 2 digit hex value

## 边界

- 这不是真实语料长尾，只看「换一份输入，账本会不会变」；合成件的覆盖面仍是合成件的。
- 「读到的」= 源包在场 ∩ 读手查问过；某份里读手根本没问的属性不进它的分母。
- 写手由产品源加载，量具用 `assertAtRef()` 逐字节守卫；工作树不干净时整批会拒跑。
- 单件账本落在 `tmp/roundtrip-corpus/<文件名>/`，不覆盖 `docs/fidelity-roundtrip.*`。
