## 一、结论先行

按「能用 / 深度 / 广度」三层分开说，混在一起会得出错误结论：

1. **主链路能用**：Writer / Calc / Impress / PDF 四组件的「打开 → 编辑 → 保存 →
   导出 PDF」全通；docx / odt / xlsx / ods / pptx / .odoc / .opd 的读写链路齐，
   PDF 查看、标注、页面管理、原地加字也齐。中文用户日常场景是可用的本地替代品。
2. **深度差在「写回去」而不是「读进来」**：docx 保真账（读手按名查问过哪些属性对）
   已到 **99.0% 按对 / 98.4% 按字面**（合成语料 701 对，已到顶）；但往返账
   （源包 → HTML → TipTap → 写手 → 再普查）只有 **正文 270/300 = 90.0%、
   图形壳 84/319 = 26.3%、合计 354/619 = 57.2%**（v0.177 补浮动图一族、
   v0.178 补图片壳、v0.179 补 a:ln、v0.180 补线端族、v0.181 补效果整片、
   v0.182 补不等宽分栏、v0.183 补节余量与 numbering legacy、v0.184 修两族值变、
   v0.185 修样式链两族显式零、v0.186 修书签两族 `w:id`、
   v0.187 修修订 / 编号两族 `w:id` / `startOverride`、
   v0.188 修画布级 `docPr|id` / `docPr|name`、v0.189 补表单域整片 8 对）。
   读得懂、写不回，仍是当下最硬的一块差距。
3. **广度差在「外壳」而不是「引擎」**：四组件各自的编辑器里功能不少，缺的是
   WPS 那层「一眼认得出」的操作体系。v0.173 补了**导航窗格与格式刷**，
   v0.174 补了 **Writer 视图缩放与内容区右键菜单**，v0.175 补了
   **独立打印预览**（单页纸面只读镜像，逐页翻页未做），v0.178 补了
   **Impress 视图缩放**（与 Writer 同一串档位），v0.179 补了 **Writer 标尺**，
   v0.180 补了 **可交互状态栏**，v0.181 补了 **逐页翻页定位**（等距页距、非真分页），
   v0.182 补了 **Impress 母版配色**（背景/文字色），
   v0.183 补了 **清除格式**（只摘字符外观、身份型 mark 整列保留），
   v0.184 补了 **PDF 首页 / 末页**，v0.185 补了 **PDF 与 Impress 共用的
   适应页宽 / 适应整页自动缩放档**，v0.186 补了
   **Impress 母版占位矩形编辑**（标题/正文两枚可拖可缩，挂了多轮的缺口），
   v0.187 把 **Writer 自动缩放档**补齐（三处 UI 共用 `fitZoom`，判断修正：
   视口宽会随侧栏开合变化）；
   仍缺 Ribbon/菜单栏、Calc 的视图缩放、版式库与 SmartArt，
   以及页面边框 / 水印 / 邮件合并 / 公式编辑器 / 数据透视表。
4. **定位差异别当差距算**：WPS 的云同步、AI 写作、模板商城、多端协同是产品形态差异；
   本项目主打「数据不出本机 + 外来格式双向保真」，这几块**明确不追**。

一句话：**日常主链路约等于，专业长尾约等于零，最贵的一笔欠账是图形壳的往返。**

## 二、口径先说清楚

| | WPS Office 桌面版 | 本项目 |
|---|---|---|
| 排版引擎 | 自有（对标 MS Office 的排版/分页/域） | WebView2 / Chromium CSS Paged Media |
| 内核 | 自研全栈 | Writer: TipTap；Calc: Univer；Impress: 自研 + pptxgenjs；PDF: pdf.js + pdf-lib；读手/写手自研 |
| 格式立场 | docx/xlsx/pptx 是主要工作格式 | 全当**外来格式**做双向保真，另存自有 .odoc/.opd |
| 天花板 | 自己 | 上游库 + 浏览器分页媒体支持度 |

**这一条决定差距性质**：打印保真上的 `@page` 串台、`:first` 穿透、暗色主题涂纸，
本质是 Chromium 的分页媒体边界，不是代码纪律能彻底解决的；WPS 直接画纸。
反过来，界面是 React 19 + CSS，改主题不用重编译——这是 WPS 没有的成本结构。

第二条口径：**「功能数量」不能跨物种直接比**。本项目的目标不是「复刻 WPS 的命令清单」，
而是「主流文件进得来、出得去、不改样」。所以下表按「用户会不会撞上」列，
不按「WPS 有多少个按钮」列。

### 本项目有、WPS 桌面版没有对等价位的

- **实时协同**：Yjs CRDT + 自写 RFC 6455 中继（房间级、无鉴权、无持久化，别当生产用）。
- **PDF 标注与页面管理写回原文件**，以及 PDF 原地加字。
- **本地优先 + 最近项目端到端加密同步**（可选）。
- **保真覆盖率有公开账**：两本账逐对可复算，变异腿能证明探针有牙；这是把 docx
  当外来格式反推语义才需要的工作量。

## 五、差距的性质（三条洞察）

1. **外壳层差距比引擎层更影响「像不像 WPS」**。用户判断一个办公套件，
   先找的是菜单、右键、格式刷、导航窗格、缩放和预览——这几样本轮之前一个都没有，
   而底下 docx 样式链的精细度其实已经不低于同类开源实现。补外壳的边际观感收益很高。
2. **「读得进写不出」是设计缺口，不是 N 个 bug**。往返账上掉了 314 对，
   其中图形壳占 275 对；逐对修要修到天亮，真因是模型没有对应的槽（v0.158 编号定义
   八对同源那条教训）。v0.177 按整族设计做掉 `wp:anchor` 一族（14 对、8.8%→13.2%），
   就是这条判断的一次实证，不是逐对打补丁。
3. **天花板在上游**。Univer/TipTap/pptxgenjs/pdf.js 决定「能表达什么」，
   Chromium 决定「纸面长什么样」。WPS 自有引擎能改的东西，本项目只能绕或记账；
   所以「与 WPS 对齐」的合理目标是**主链路 + 高频交互**，不是全套命令。

## 八、没量 / 不确定的（诚实清单）

- **没跑真机 WPS 对撞**：仓库的实机回归是 Word 16.0 / PowerPoint 16.0 COM，
  本机没有 WPS 的自动化回归链路；本评估是纸面对照 + 本仓库量具，不是双份真件互撞。
- **WPS 功能面按桌面版常见形态列举**，未逐版本核对，也不含云/AI/会员增值。
- **xlsx / ods / pptx 的属性级往返账**：只有 pptx 有一份 77 对夹具的保真账，
  表格侧没有公开的属性级账；99.0% 不能外推到它们。
- **Univer 函数覆盖度**从未量过。
- **十二轮性能数字都来自纯合成夹具**（N 段同构段落、STORE 压缩；
  v0.174 另有一路「每段 pict+drawing 各一枚」的图形密集件；v0.175 是每页带
  背景图/形状图/备注/rels 的合成 pptx；v0.176 是 1600 填充段 + C 条批注的
  合成 docx），量的是解析、遍历与序列化成本，不是真件的打开耗时；
  真件上还有图片、样式、关系表的开销。
  v0.174 起的判据取**同进程 A/B**（改前读手导出成副本，两腿交替顺序各 10 样本），
  因为跨进程两次独立运行的绝对值随机器负载浮动可达 20% 以上，不能相减。
- **Writer 打印预览是单页纸面只读镜像**，不切页、不重排；逐页翻页与多页并排
  仍未做，真正的分页交给 Chromium 的 `@media print`。
- **PDF 查找替换**沿用「盖底色 + 画新字」的内容流改字：新字明显长于原字时不自动
  缩放 / 重排；定位不了的命中如实跳过；写回前页面仍显示原文。OCR、PDF→Word
  仍未做。
- **浮动图/图片壳只保真、不上屏**：写回的壳属性让 Word 里仍是浮动图、仍是
  四周环绕、仍带裁剪与翻转，但 Web 流式排版没有文字环绕，编辑器里图片仍按
  内嵌位置摆放；v0.178 回写了 `wp:wrapSquare/@wrapText`、v0.179 回写了
  `a:ln` 三枚线型属性、v0.180 回写了四枚线端子元素、v0.181 回写了
  `a:effectLst` 三枚效果元素；`positionH/V` 的 `posOffset` 与
  `sizeRelH/sizeRelV` 相对尺寸仍未回写。
- **自动缩放档（三处 UI）只有纯函数与源码级断言**：七档之外
  共用 `fitZoom` 给了「适合页宽 / 适合整页」两枚按钮；Impress 的未缩放页面
  尺寸靠 `getBoundingClientRect()/当前 zoom` 还原，这个假设与 CSS zoom 下
  形状拖动比例自洽一样，都未做真机浏览器对撞。Writer v0.187 补齐自动档
  （判断修正：视口宽会随侧栏开合变化），同样没做真机对撞。

  标尺拖动按 1mm 网格、工具条缩进按钮按 32px，两个入口步长不同（都走绝对设定）。
  标尺只做了固定版心的刻度与三枚滑块，多栏时按整版心显示，没有逐栏标尺。
- **效果整片只回写三枚自闭合元素的属性**：源件描边里的
  `a:solidFill/a:schemeClr` 填充仍未回写（包发的是 `a:noFill`）；三维族
  `scene3d`/`sp3d`/`props3d` 在夹具里被塞进 effectLst 内部、按 schema 非法，
  本轮刻意不复刻，`lightRig`/`sp3d`/`props3d` 共 8 对仍在账上。

  时间戳与包的随机关系号两腿天然不同，归一后比的是各部件内容。
