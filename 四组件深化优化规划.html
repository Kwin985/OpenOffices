01

四条规划原则与一条边界

先立规矩，再排工作项

① 用户可感知优先于字节保真

同样的精力，"屏上看见页、存盘不丢格式"比"多认一种冷门边框变体"回报高一个档。保真工作按用户抱怨频率排，不按 OOXML 章节顺序排。

② 主轴一件大事 + 支线小额清账

每个组件只立一条主轴（一个版本能讲清的叙事），其余是可随时插队的清账项。过去九个版本连啃文档表格就是这种节奏的正面示范，但四个组件不能同时开四条主轴。

③ 优先吃依赖里现成的能力

pdf-lib 的 getForm() 就在依赖树里没接线，Univer 支持注册自定义函数——很多"缺的能力"其实不用新内核，先把已有的接完。

④ 用实机回归锁住，而不是靠记忆

Word/Excel/PowerPoint COM 实机回归是这套项目最值钱的资产，但它现在靠本机手工跑（README 里 Word COM SaveAs 挂起的故障就是证据）。先把回归固化，再动格式层，否则每一步都在裸奔。

边界声明：本规划不含格式扩展，因此 OCR、PDF→Word/Excel 转换、宏/VBA 这类跨格式能力全部不列入。列进来的每一项要么属于既有格式的保真（开回来不丢、存回去不走样），要么属于既有格式的编辑能力（能改出别人格式里合法的内容），要么属于体验。
02

文字 Writer · docx / odt / odoc

现状：TipTap 流式内核，格式往返已到 w:spacing/pBdr/脚注尾注/TOC 域这一层，但"页"在屏上不存在

📄

主轴：把"纸"搬回屏幕

覆盖 v0.88–0.95 表格九连版的自然延续
分页所见即所得的轻量实现。不必造 Word 级排版引擎——v0.33 已有分页参考线与页数指示，v0.93/0.94 已能把纸面量准，缺的是把"打印侧的测量"搬回编辑态，让参考线从"近似提示"升级为"逐页精确边界"。分三步走：只读分页预览 → 编辑态页框内流式 → 度量与 Word 对齐。 为什么是主轴：这是"文字处理"这个品类的基本盘。公文、论文、合同场景里，屏上分不了页 = 用户不敢用它写正式文档。
P0保真与度量补课（先让纸面对得起屏幕）约 3–5 个版本
1
屏上分页预览（只读 → 编辑态渐进）

借用 sheet-print-measure 的测量思路，在编辑区按版心切页渲染页边界；第一阶段只做只读预览，第二阶段编辑态套页框背景（流式排版不变，页界随内容实时下移）。

依赖：无
2
纸面度量对齐 Word

修掉 README 实测的三笔账：纸面行高比 Word 厚约 3×；px 存整数的 ±0.25pt 漂移；屏上 626px 与 contentPxOf 627px 的 1px 口径差。

依赖：无
3
表格读侧补完（v0.89–0.95 的欠账）

读侧目前只吃 w:gridCol——补 w:tblLayout / w:tcW / w:tblCellMar / w:trHeight；嵌套表按所在单元格真实版心算宽；中途夹表头行跨页重复；ODT 列宽两头往返（现在写侧零枚 table:table-column）。

依赖：无
4
段落边框收尾

w:between 第五边（往返件已实测丢 7 处）；异形线型不再静默降档为实线；w:space 的可达性。

依赖：无
P1结构化能力（长文档与企业场景的门槛）约 4–6 个版本
5
命名样式体系（样式面板）

段落样式 / 字符样式的命名、修改、继承；docx 读侧不再把样式链摊平成直接格式，写侧回写 styles.xml。这是长文档结构化的根，也是 docx 保真从"逐属性"升到"逐样式"的前提。

依赖：P0-3 完成后动
6
修订（Track Changes）

docx w:ins/w:del 与 ODF text:change 双向往返 + 接受/拒绝 UI。与已有的批注体系（comments + commentsExtended 已实机回归）合成完整审阅闭环。缺这一项，法务/公文/出版场景进不去。

依赖：无
7
分节与多套页眉页脚

分节符 + 每节独立页眉页脚页码（现在全局一套）。公文"正文从第 1 页起编、封面无页码"靠它。

依赖：P0-2
P2长文档体验穿插进行
8
解析侧拆片与导航

fid / odt / JSON.parse 仍是一口气解析（v0.87 只拆了"喂"这一段）；补大纲导航侧栏（TOC 节点已有，缺常驻侧栏）。

依赖：无
9
公式只读渲染升级

OMML/MathML 从"线性化降级"（x^2、√(y)）升级为只读排版渲染；仍不做编辑器。

依赖：无
03

表格 Calc · xlsx / xls / ods / csv

现状：往返覆盖面已是四组件最广（样式/合并/冻结/公式/规则/批注/链接/页面设置全通），但写侧是"整包重写"

📊

主轴：从"整包重写"到"保留式写回"

xlsx 保真的根，README 里已如实记着
现在 write_xlsx 是 Workbook::new() 整包重写——第三方件里读侧不认识的属性（未知 sheetPr、扩展格式、第三方命名空间的一切）活不过一次存盘。用户"打开又保存"一次，文件就被悄悄洗了一遍。改成 patch-in-place（只重写我们管的那几个部件，其余字节原样保留）或把载荷覆盖面扩到"读侧认识的全部"。 为什么是主轴：往返覆盖面已经够宽了，再宽一寸不如把"存盘即损"这个根挖掉。这一条修好，之前所有保真工作的价值才落得住。
P0保真收口约 3–4 个版本
1
保留式写回（主轴本体）

zip 部件级 diff 写回：只动我们重写的 sheet/styles 部件，未知部件与未知属性原样搬运。测试判据换血——"第三方件存一遍再读回，字节差为零的部分逐件列举"。

依赖：无
2
归一化统一：屏幕层搬进同一份账

v0.58–0.61 留下的分叉：文件说 14pt 时纸对而屏不对；列宽 MDW=7 只对 Calibri/11，底数抬到 14pt 列宽全错；行高非整数像素被 as u32 截断。三个一起收，判据是"同一份件屏、纸、字节三处读数一致"。

依赖：无
3
ODS 补到 xlsx 同水位

现在记边界账的三块：ODS 图表、三类规则、页面设置；再加 ODF 字族三条变体（-asian/-complex）与 office:font-face-decls 映射——中文场景 font-face-decls 不接，字族往返就是碰运气。

依赖：无
P1能力补强（不是新格式，是既有格式的深度）约 4–6 个版本
4
公式函数覆盖度审计与补齐

对 Excel/WPS 高频函数（查找引用 / 文本 / 日期 / 条件聚合）建覆盖矩阵；Univer 支持注册自定义函数，缺的按矩阵补。测试判据：WPS/Excel 里跑同样一组公式，结果逐格一致。

依赖：无
5
最小数据透视

Univer 社区版无透视插件。自建最小版：拖字段 → 聚合（求和/计数/均值）→ 结果写入新表；先不做透视缓存往返（那一步可后置，xlsx 里 pivotTable 部件读侧可先记边界账）。

依赖：无
6
图表类型与坐标轴往返扩展

VChart 路线已通，补齐常用类型（饼/条形/组合）与坐标轴格式、图例位置的 xlsx 往返；Excel 实机核色。

依赖：无
P2规模与收尾穿插进行
7
大表分段喂

文档那头 v0.87 的"阈值分批喂 + 读全闸门"搬到表格（现在表格没有这本账，写出口也没有闸）。

依赖：无
8
打印记账清零

"算不出的一律进状态栏记账"收敛为零——打印保真已经是强项，别留尾巴。

依赖：无
04

演示 Impress · pptx / opd

现状：母版/备注/动画的 pptx 往返已做到 PowerPoint 实机回归级别，但编辑器本身是"版式驱动"——用户不能自由摆放一个文本框

🎬

主轴：从"版式驱动"到"画布驱动"

编辑模型已核实：内容只有标题 + 要点行 + 一张图，位置由版式决定
自由元素是"能放 PPT"和"能做 PPT"的分水岭。现在四套版式（标题/要点/图片/空白）决定了页面上只能有什么、在哪。用户想加个侧栏文本框、画个箭头、把图表挪个位置——都做不到。给画布加自由文本框与基础形状（矩形/椭圆/线条），任意摆放、缩放、旋转，配上网格与对齐辅助线。 为什么是主轴：保真侧它已经把最难啃的 timing 树啃完了，继续深挖保真的边际收益很低；而"做不了自己的 PPT"是产品层面的天花板。
P0画布与接线（主轴本体）约 5–7 个版本，最大单件
1
自由文本框与基础形状

元素模型从"版式槽位"升级为"元素数组"（文本框/形状/图片，带 x/y/w/h/旋转/层级）；画布网格、对齐吸附、层级调整。旧版式自动迁移为等效元素布局（.opd 旧文件无损打开）。

依赖：无
2
元素稳定 id 与动画接线修正

现在导出靠"正文首行文本反查 cNvPr id"定位形状（pptxgenjs 不给可预测 id）——自由化之后元素自带稳定 id，timing 树映射从"反查"改为"直取"，顺带把反查这条脆弱链路拆掉。

依赖：P0-1
3
母版可编辑 + 主题色自定义

母版几何/配色现在只读还原；开放母版编辑与任意主题色（现在 6 套固定），写侧经 clrScheme 回写 pptx。

依赖：P0-1
P1动画与往返补全约 3–4 个版本
4
动画窗格

逐条动画现在每页只能选一种效果——升格为按元素列表管理：顺序、延时、触发（单击/随上一条）；补强调动画（放大/变色）。

依赖：P0-2
5
pptx 往返剩余三件

图表缓存值从只读数据表升级为可编辑图表；SmartArt 降级保留为图片（现在展平成列表，形状外观丢失）；媒体元素（视频/音频）至少占位不丢。

依赖：P0-1
6
放映工具

墨迹标注（放映中画笔）、黑屏/白屏、数字键跳页——演讲者视图已经很完整，补这三件就齐了。

依赖：无
P2模板族低优先
7
场景化模板族

11 个通用模板扩为场景族（工作汇报/产品发布/教学课件），自由画布完成后模板才真正有表达力。

依赖：P0-1、P0-3
05

PDF · 查看与标注

现状：查看、标注（含第三方注解导入）、页面管理、加密打开、大文件分段读取都已完整；但有两件"该有而没有"的——打印没接、表单没接

📕

主轴：从"查看 + 标注"走向"处理"

依赖树里现成的能力还没接完
先接现成的，再谈新的。pdf-lib 的 getForm() 表单读写 API 就在依赖里（零新依赖），而 PDF 标签现在连系统打印都没接——这是四组件里唯一一个"打印不出去"的。主轴就是把"打开看过、签过字"变成"填过表、打出来、盖过章"的完整处理链。 为什么是主轴：投入最小、品类补齐最快。表单 + 打印 + 图章三件事做完，PDF 从"阅读器"变成"处理工具"，这是用户换工具的理由。
P0接现成的（性价比全场最高）约 2–3 个版本
1
AcroForm 表单填写与保存

pdf-lib getForm() 现成：文本框、复选、单选、下拉的识别、填写、保存回写；只读字段锁定。合同/申报表场景的高频刚需。零新依赖。

依赖：无（API 已在依赖树）
2
PDF 打印接线

四组件里唯一打不出去的一个。接系统打印对话框（文档那头 window.print + 表格那头 PrintToPdf 的路都现成）。

依赖：无
3
图章 / 图片标注

图片贴页（签名图章、骑缝章场景），复用已有标注写回通道（pdf-lib 低层 Annotation 字典构造已通）。

依赖：无
P1管理与检索约 3 个版本
4
标注汇总面板

全部标注列表（按页/按作者/按类型过滤）、点击定位、一键导出标注摘要文本。审阅场景刚需，数据都在，只差面板。

依赖：无
5
搜索工程化

README 自记的三笔账一起清：从"第 1 页扫整本"改增量索引；匹配结果跨查询缓存（现在换个词全部重扫）；"500+" 诚实补报总数。

依赖：无
6
页面管理增强

插入空白页、页码重排、批量旋转；现有五路（旋转/删除/提取/合并/拆分）补真大件整趟回归（README 记着没量过）。

依赖：无
P2评估项先评估再立项
7
PDF 导出长图 / 纯文本

复用已有渲染管线，成本低；签名域只读验证工作量大，先评估证书生态再决定。

依赖：无
06

横切工程 · 四个组件共享的三件事

不属于哪个组件，但不做它们，四个组件的深化都会反复踩坑

① 纸面契约统一（打印/导出管线）

现在三套实现并存：文档走 @media print + window.print，表格是 sheet-print 三件套约 3600 行自建测量，演示是每页全出血——而 PDF 干脆没有打印。打印/导出是四个组件唯一共享的用户出口，抽一层公共"纸面契约"（纸张/边距/缩放/页眉页脚语义），四个组件的纸面行为才有一致性，也省掉三份重复维护。

② 实机回归自动化（质量底座）

Word/Excel/PowerPoint COM 实机回归 + OOXML 字节差分是这套项目最值钱的资产，但目前跑在本机手工触发——README 已记录 Word COM SaveAs 环境故障、孤儿属主文件需人工清理这类脆弱性。把它固化成可重复的冒烟套件（含探针预检），是所有 P0 工作的前置。先立回归，再动格式。

③ 已知问题账本化

README 里挂着一百三十多条未勾选的已知问题与未量边界，散在九十个版本的日志里。按组件建 issue 账本，每版本定额消化（比如 3 条），新发现的边界直接入账。没有账本，"做透"就永远不知道还差多少。

④ 读写闸门补齐（性能债）

v0.87 的"阈值分批喂 + 读全闸门"只做在文档一头，表格与演示没有这本账、写出口也没有闸；解析侧 fid/odt/JSON.parse 仍是一口气。对齐文档那头的方案即可，属于还债不是新功能。

07

三阶段节奏

主轴不并行：同一时间只有一个组件在开大件

阶段一
收口与低垂果实
横切打底 + 三个组件的 P0 清账
  • 前置：实机回归自动化立起来（横切②）；已知问题入账本（横切③）
  • Calc：保留式写回——本规划回报率最高的单件
  • PDF：表单 + 打印 + 图章三连，品类感立刻不同
  • Writer：度量对齐与表格读侧补完（不动主轴）
阶段二
两大主轴
文字分页 · 演示画布（错峰，先文字后演示）
  • Writer 主轴：屏上分页预览 → 编辑态页框 → 多节页眉页脚
  • Impress 主轴：自由元素 → 稳定 id → 母版可编辑（紧随其后）
  • 穿插：归一化统一（Calc P0-2）、标注面板与搜索工程化（PDF P1）
  • 横切：纸面契约统一层，在两条主轴都落定后抽
阶段三
能力补强
修订 · 样式 · 透视 · 动画窗格
  • Writer：命名样式体系 → 修订（Track Changes）——企业场景两块敲门砖
  • Calc：函数覆盖度审计 → 最小透视
  • Impress：动画窗格 → pptx 往返剩余三件
  • 收敛：打印记账清零、模板族、大表分段喂
v1.0 门槛建议：四个组件各自主轴完成 + 各自 P0 清零 + 横切①②落定。到那一步，这个项目的自我介绍可以从"开源办公套件"升级为"轻量、本地优先、格式往返可信的办公套件"——后半个定语，就是这一整个规划买回来的东西。
规划依据　源仓实查（2026-10-07）：PptEditor.tsx 确认演示为版式驱动模型（内容仅标题/要点/图片，位置由版式决定）；PdfViewer.tsx 确认无打印接线、无 AcroForm；pdf-lib getForm() 确认在依赖树内可用；paragraph-style.ts 确认文字侧为直接格式属性（无命名样式体系）；README 95 版迭代日志中 130+ 条未勾选已知问题（ODT 列宽、w:between、MDW 列宽、整包重写、搜索扫法、COM 回归脆弱性等）逐条对号入座。
排序口径　P0＝保真收口或主轴地基；P1＝企业场景能力；P2＝体验与评估项。版本数按该项目历史节奏（一版一个可验证主题）估算，供参考非承诺。
